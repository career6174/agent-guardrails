# 如果冇辦法成套搬過去

一個指令安裝係最快嘅路。呢一頁寫畀行唔到嗰條路嘅人。可能你用緊第二款 AI 助手，可能公司電腦唔畀改設定，可能你自己已經有一套攔截器，又或者你想先明白個諗法，唔想亂跑人哋嘅程式。第 1 節講思路，第 2 節搵返自己屬於邊種情況。

[English](ADAPT.md)

## 1. 成個思路，一步一步講

呢個 repo 入面每一樣嘢，都係重複行下面呢個圈得返嚟。

```
AI 助手整出真實損失
        │
        ▼
問題一：程式驗唔驗得到？ ── 得 ──▶ 喺助手落手嗰一下加一個細檢查（攔截器）
        │ 唔得
        ▼
問題二：第二個助手驗唔驗得到？ ─ 得 ─▶ 搵一個冇睇過過程嘅審查員，淨係畀成果佢睇，要佢逐項攞證據
        │ 唔得
        ▼
寫低做守則；第二次被無視，就升級做問題一或者問題二嘅做法
```

成個設計靠五個諗法撐住。乜都唔攞，都攞走呢五個。

**1. 用強制，唔用勸**
- 改之前： 提示入面寫「千祈唔好永久刪檔」，做到第 40 步就唔記得。
- 改之後： 每個指令執行之前有程式睇一次，危險嘅直接唔畀行。
- 生活例子： 路邊限速牌，對比引擎入面嘅限速器。

**2. 喺落手嗰一下檢查**
- 改之前： 出咗事先翻紀錄搵錯。
- 改之後： 設兩個關卡：每次用工具之前，同埋助手講「做完」嗰一刻。
- 生活例子： 機場安檢設喺閘口，唔係設喺目的地。

**3. 做嘅同核嘅唔同人**
- 改之前： 寫報告嗰個助手自己話自己啱。
- 改之後： 第二個助手冇睇過過程，打開真正嘅成果，逐句對證據。
- 生活例子： 申請付款嘅人，唔可以自己批自己嗰張單。

**4. 檢查壞咗要識讓路**
- 改之前： 攔截器有錯就永遠擋住，成個工作卡死。
- 改之後： 攔截器自己出錯就放行；同一批檔案擋夠 3 次就放手，兼且講明。
- 生活例子： 電掣跳咗，永遠可以用手推返上去。

**5. 樣樣都數住**
- 改之前： 「感覺安全咗」。
- 改之後： 每次攔截同每個判決都記一行，「有冇用」可以用數字答。
- 生活例子： 舖頭有數退貨，先知邊件貨有問題。

點解用攔截器，唔係寫長啲個提示：提示只讀一次，長工作入面要同好多嘢爭注意力。攔截器喺模型外面行，第 1 次同第 500 次一樣。

點解要第二個助手，唔係叫佢自己檢查：叫助手檢查自己嘅結論，佢多數會話啱。呢個 repo 第一次送審嗰陣測試全部通過，審查員照樣搵到 6 種方法繞過刪檔攔截。

## 2. 搵返你嘅情況

| 你嘅情況 | 點做 | 攞到乜 |

| Claude Code，Windows | `git clone` 之後 `python install.py`（見 [INSTALL.md](../INSTALL.md#other-routes)） | 全套 |
| 唔可以改個人設定（公司電腦） | 喺專案入面跑 `CLAUDE_CONFIG_DIR=./.claude python3 install.py` | 全套，只限嗰個專案 |

| 自己已經有攔截器 | 照跑安裝程式：佢只會加，唔會改你原有嘅。如果有一個同你嘅重疊，就人手裝其餘嗰啲 | 你揀嘅嗰幾個 |
| 只想要其中一個 | 喺 `hooks/` 抄一個檔，設定加一項 | 嗰一個 |

| 想自己設計攔截器 | 第 5 節 | 成套方法 |

## 3. 冇攔截功能：純文字版

冇攔截器即係冇強制，守則有時會被跳過。但仲係好過乜都冇，因為審查嗰一步會執返守則漏咗嘅嘢。

1. 將 [`templates/CLAUDE.md`](../templates/CLAUDE.md) 嘅內容，放入你個工具每次開工都會讀嘅地方（系統提示、專案指示檔、置頂筆記），填返尖括號嗰啲位。
2. 收任何成果之前，開一個**全新**對話，先貼 [`agents/reviewer.md`](../agents/reviewer.md) 嘅正文，再貼成果本身。唔好貼作者嘅總結。新對話先叫做獨立審查。
3. 叫助手起任何新嘢之前，用 [`agents/scout.md`](../agents/scout.md) 加你想要嘅嘢，照做一次。
4. 數兩個星期：審查員指出問題嘅有幾多份，當中真係有錯嘅有幾多。呢個數話你知值唔值得搞強制。

同有攔截器比，少咗乜：刪檔同重試兩個攔截（冇嘢可以擋住一個指令），同埋「一定有審」嘅保證（要靠你自己記得）。

## 4. 搬去第二款 AI 助手

識跑指令嘅工具，多數都有方法喺「用工具之前」或者「一輪完結」嗰陣跑一個程式。名唔同，形狀一樣。每一件需要宿主提供乜：

| 件 | 讀乜 | 點樣講「擋」 | 搬得走嘅部分 |
|---|---|---|---|
| `safe_delete_guard.py` | 就嚟要跑嘅指令 | 結束碼 2，原因寫去 stderr | `check(command)`：純函數，回傳原因或者 `None`，冇任何 Claude 專用嘅嘢 |
| `repeat_guard.py` | 工具名、工具輸入、工作階段編號 | 結束碼 2；之前先出一個 JSON 警告 | `fingerprint()` 同 `record()`：將呼叫變成指紋，喺最近 20 次入面數 |
| `review_gate.py` | 工作紀錄（一行一個 JSON） | 喺 stdout 印 `{"decision": "block", "reason": ...}` | `needs_review(lines)`：上次審查之後寫過邊啲成果 |
| `agents/reviewer.md`、`agents/scout.md` | 冇 | 唔適用 | 純 Markdown 提示；只有最頂嗰幾行係 Claude 專用 |
| `templates/CLAUDE.md`、`docs/PLAYBOOK.md` | 冇 | 唔適用 | 純文字；改名做你個工具會讀嘅檔（例如 `AGENTS.md`） |

三個攔截器由 stdin 收嘅 JSON 有呢幾個欄：`tool_name`、`tool_input`（指令放喺 `tool_input.command`）、`session_id`，審查閘另外要 `transcript_path`。如果你個工具嘅欄名唔同，寫十行轉接程式改名，就係成個搬遷。

最快嘅做法係叫你自己個助手搬，將下面呢段貼畀佢。

```
Read https://github.com/career6174/agent-guardrails : docs/ADAPT.md, the three files in hooks/, and tests/test_hooks.py.
Then look up how hooks (or the closest equivalent) work in <name of my tool>.
Port the three guards so they run in my tool. Keep the check logic unchanged; write only a thin adapter for the input and output format.
Port the tests too and run them. Show me each file before you install it, and tell me plainly which guard could not be ported and why.
```

呢度只喺 Claude Code 測試過。其他工具請當上面張表係地圖，信搬過去之後跑通嘅測試，唔好信呢一頁。

## 5. 五步整你自己嘅攔截器

呢個 repo 每一個攔截器都係咁整出嚟。

1. **由事故開始，唔係由諗法開始。** 寫一句：助手做咗乜、代價係乜。冇事故就唔整。（我哋嗰句：一次 `git stash` 掃走 6,033 個未儲存嘅檔案。）
2. **寫一個啱啱好擋得住嘅最細檢查。** 一個檔、唔靠外面嘅套件、一個純函數，收入動作，回傳原因或者乜都冇。細到一次過讀得完。
3. **壞咗要放行，而且要測。** 餵亂碼、唔存在嘅檔、壞咗嘅狀態檔。每一種情況助手都要可以繼續做嘢。
4. **搵另一個助手嚟攻。** 將程式交畀審查員，叫佢搵繞得過嘅寫法。每一個繞過都變成一個測試。呢度嘅刪檔攔截就係咁，五輪之內由 9 個測試加到 62 個。
5. **記錄，兩個星期後檢討。** 數攔截次數。從來唔響嘅可能根本唔需要；正常工作都響嘅就係寫錯，要改或者拆。

程式驗唔到、第二個助手又驗唔到嘅守則，只係願望。鍾意可以留喺指示檔，但唔好靠佢。

## 6. 呢套嘢幫唔到你嘅地方

- 佢係安全帶，擋嘅係唔小心。佢唔係保安邊界：刻意偽裝過嘅指令係過到嘅。
- 審查員本身都係 AI。佢指出問題，等於「值得睇一睇」，唔等於「證實有錯」。
- README 嘅數字嚟自一個人、一個月嘅環境。引用之前請先量度你自己嗰邊。
